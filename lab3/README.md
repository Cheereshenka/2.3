# Что делает программа

Это графический **органайзер задач**. Пользователь может:

1. создавать задачи;
2. указывать название, описание, исполнителя, срок, статус и категорию;
3. редактировать выбранную задачу;
4. искать задачи по названию, исполнителю и описанию;
5. одновременно фильтровать задачи по статусу и категории;
6. сортировать задачи по столбцам;
7. помечать задачу выполненной;
8. удалять задачу;
9. выбирать способ хранения данных;
10. синхронизировать данные между тремя хранилищами.

В программе предусмотрены три варианта хранения:

- **collection** — данные только в оперативной памяти;
- **file** — файл `properties`;
- **database** — база SQLite.

---

# Что происходит при запуске

После запуска `Launcher` передаёт управление JavaFX-приложению `App`.

`App`:

1. создаёт графическое окно;
2. загружает настройки из `config.properties`;
3. создаёт три реализации DAO;
4. выбирает активное хранилище;
5. создаёт `TaskService`;
6. заполняет элементы интерфейса статусами и категориями;
7. показывает таблицу задач;
8. подключает обработчики кнопок, поиска и фильтров.

Архитектура:

```text
                         App / JavaFX
                              |
                              v
                         TaskService
                              |
                              v
                           TaskDAO
                    /         |         \
                   /          |          \
                  v           v           v
        CollectionTaskDAO  FileTaskDAO  DatabaseTaskDAO
             память        properties      SQLite
```

Фабрики создают соответствующую реализацию DAO:

```text
DAOFactory
   |
   +-- CollectionDAOFactory
   +-- FileDAOFactory
   +-- DatabaseDAOFactory
```

Отдельный `SynchronizationService` работает сразу со всеми источниками и приводит их к общему состоянию.

# Что такое Task

`Task` — основная модель приложения.

Она содержит:

- `UUID id` — уникальный идентификатор;
- `title` — название;
- `description` — описание;
- `executor` — исполнитель;
- `deadline` — срок;
- `status` — статус;
- `category` — категория;
- `updatedAt` — время последнего изменения;
- `deleted` — логическая метка удаления.

Статусы:

```text
Новая
В работе
Выполнена
```

Категории:

```text
Работа
Учёба
Личное
```

При создании `Task` проверяется корректность обязательных данных. Название и исполнитель не могут быть пустыми.

---

# Как создаётся задача

Когда пользователь нажимает **«Сохранить задачу»**, программа передаёт значения формы в:

```text
TaskService.save(...)
```

Если это новая задача, создаётся новый UUID:

```text
форма
  ↓
TaskService.save()
  ↓
new Task(UUID.randomUUID(), ...)
  ↓
TaskDAO.upsert(task)
  ↓
активное хранилище
```

Если задача уже существует, создаётся новая версия той же задачи через `revised(...)`. При этом изменяется `updatedAt`.

# Поиск и фильтрация

Метод:

```text
TaskService.find(...)
```

получает:

- поисковую строку;
- статус;
- категорию.

Поиск выполняется сразу по:

- названию;
- исполнителю;
- описанию.

Фильтры применяются совместно.

Например:

```text
Поиск: Иван
Статус: В работе
Категория: Учёба
```

В результате останутся только задачи, которые одновременно соответствуют всем трём условиям.

Просроченные незавершённые задачи подсвечиваются в таблице.

# Три способа хранения

## 1. CollectionTaskDAO

Данные хранятся в:

```text
Map<UUID, Task>
```

Это оперативная память. После закрытия программы такие изменения не сохраняются.

## 2. FileTaskDAO

Данные записываются в файл:

```text
data/tasks.properties
```

Файл использует UTF-8 и временный файл при сохранении, после чего выполняется замена основного файла.

## 3. DatabaseTaskDAO

Используется SQLite.

По умолчанию база:

```text
data/organizer.db
```

DAO создаёт таблицу `tasks`, если её ещё нет, и использует параметризованные SQL-запросы.

# Зачем нужны DAO и Abstract Factory

**DAO** отделяет бизнес-логику от конкретного способа хранения.

`TaskService` не знает, где физически лежит задача. Ему достаточно интерфейса:

```text
TaskDAO
```

Поэтому один и тот же сервис может работать с:

```text
CollectionTaskDAO
FileTaskDAO
DatabaseTaskDAO
```

**Abstract Factory** используется для создания нужной реализации:

```text
DAOFactory
 ├── CollectionDAOFactory
 ├── FileDAOFactory
 └── DatabaseDAOFactory
```

Благодаря этому код интерфейса и бизнес-логики не зависит напрямую от SQLite или файла.

---

# Синхронизация

Кнопка **«Синхронизировать все»** запускает:

```text
SynchronizationService.synchronize()
```

Сервис сначала читает все три источника:

```text
collection
file
database
```

Для каждого UUID выбирается самая свежая версия по `updatedAt`.

Если даты совпадают и одна версия помечена как удалённая, приоритет получает удаление.

После объединения итоговый набор записывается обратно во все три источника.

Схема:

```text
Collection ──┐
             │
File ────────┼──> SynchronizationService
             │          |
SQLite ──────┘          v
                    общий набор
                         |
              ┌──────────┼──────────┐
              v          v          v
         Collection     File      SQLite
```

Это позволяет не возвращать удалённые задачи из старых копий.

---

# Что происходит при удалении

Удаление является логическим.

Физически задача не исчезает сразу. Для неё устанавливается:

```text
deleted = true
```

Это важно для синхронизации.

Если просто удалить запись из одного источника, старая копия из другого источника могла бы снова вернуть её.

Метка удаления позволяет распространить факт удаления на остальные хранилища.

# Что сказать преподавателю

> В лабораторной работе реализован графический органайзер задач на JavaFX. Основная бизнес-модель представлена классом `Task`, а работа с данными вынесена через интерфейс `TaskDAO`. Для разных способов хранения реализованы три DAO: коллекция в памяти, файл properties и база SQLite.
>
> Для создания соответствующих DAO используются фабрики `CollectionDAOFactory`, `FileDAOFactory` и `DatabaseDAOFactory`, что демонстрирует применение Abstract Factory.
>
> `TaskService` содержит бизнес-логику поиска, фильтрации, создания, изменения, удаления и завершения задач и не зависит от конкретного хранилища.
>
> Отдельный `SynchronizationService` объединяет данные из трёх источников. Для каждой задачи сравнивается время изменения, поэтому более свежая версия распространяется во все хранилища. Логическое удаление сохраняется, чтобы старые копии не восстанавливали удалённые задачи.
>
> В приложении также предусмотрено логирование операций и автоматические тесты JUnit и Mockito.

## Примечание

В исходной лабораторной был указан **Java 21**, а в одном тесте использовался `getFirst()`, появившийся в более новых версиях Java. Для нашей общей среды я заменил это на совместимый с Java 17 вариант `get(0)` и выставил в Maven `maven.compiler.release=17`. Остальная архитектура и логика лабораторной сохранены.
